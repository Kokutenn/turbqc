## Defects found and fixed

**DEF-01** (Parallel run on the live archive, batch 2026-10-24)

- Symptom: One report present in v1 but missing in v2 (key check), which also broke the pirep volume reconciliation for that hour. Both were unexplained, so the decision was NO-GO.
- Root cause: The provider does not quote raw_text. A PIREP remark contained a comma ("...ONCE OUT OF CLOUDS, CEILINGS 011 MSL"), so the line had 45 fields instead of 44. v2 quarantined it as malformed and lost a valid report. v1 happened to re-join the overflow into the message.
- Fix: feed.parse re-joins any overflow into raw_text (the last column); only lines that cannot be repaired count as malformed.
- Verified by: test_overflowing_free_text_is_repaired; rerun of the live parallel run (SO-01 to SO-04 green)
